# UD02: Introducción a PHP (continuación)

En esta parte de la unidad se estudia cómo intercambiar datos entre el navegador y un script PHP: parámetros en la URL, formularios, métodos HTTP y respuestas del servidor.

## Objetivos

- Leer parámetros enviados mediante la URL con el método `GET`.
- Crear formularios HTML y procesar sus datos en PHP.
- Diferenciar los métodos HTTP `GET` y `POST`.
- Validar y filtrar los datos recibidos antes de utilizarlos.
- Generar respuestas HTML y códigos de estado HTTP adecuados.

## 1. Petición y respuesta HTTP

La comunicación entre un navegador y un servidor web se realiza mediante peticiones y respuestas HTTP. Una petición puede incluir un método, una ruta, cabeceras y, en algunos casos, un cuerpo con datos. La respuesta incluye un código de estado, cabeceras y, habitualmente, un documento HTML.

En esta unidad se utilizarán principalmente estos métodos:

| Método | Uso habitual | Dónde viajan los datos |
| --- | --- | --- |
| `GET` | Consultar o solicitar un recurso | En la URL, como parámetros de consulta |
| `POST` | Enviar datos para ser procesados | En el cuerpo de la petición |

`GET` se utiliza para obtener información; sus URLs pueden guardarse en marcadores o repetirse. `POST` es habitual al enviar datos que crearán o modificarán información. Ninguno de estos métodos cifra los datos: para proteger la comunicación se necesita HTTPS.

## 2. Parámetros en la URL: método GET

Los parámetros de consulta se escriben después de `?` en la URL. Se separan con `&` y siguen el formato `nombre=valor`:

```text
productos.php?category=books&page=2
```

PHP recibe estos parámetros en el array superglobal `$_GET`. Sus claves son los nombres de los parámetros:

```php
<?php
$category = $_GET['category'] ?? 'all';
$page = $_GET['page'] ?? '1';

echo 'Categoría: ' . htmlspecialchars($category, ENT_QUOTES, 'UTF-8');
echo 'Página: ' . htmlspecialchars($page, ENT_QUOTES, 'UTF-8');
```

`htmlspecialchars()` convierte caracteres especiales en entidades HTML antes de mostrarlos. Es importante aquí porque los valores de `$_GET` los controla quien visita la página: sin escapar, podrían interpretarse como HTML o JavaScript. Úsala al insertar datos no confiables en HTML; `ENT_QUOTES` también escapa las comillas y `'UTF-8'` indica la codificación.

Por ejemplo, se deben escapar valores como `<script>alert('XSS')</script>`, `<b>oferta</b>` o `Tom & Jerry` si se van a mostrar en HTML: así se presentan como texto y no se interpretan como etiquetas o código.

No se debe asumir que una clave existe ni que su valor tiene el formato esperado. El operador `??` proporciona un valor predeterminado cuando la clave no existe o es `null`. Los valores recibidos son texto; si se espera un entero, hay que validarlo:

```php
<?php
$page = filter_input(INPUT_GET, 'page', FILTER_VALIDATE_INT);

if ($page === false || $page === null || $page < 1) {
  $page = 1;
}
```

`filter_input()` lee un dato de una fuente externa —en este caso, `$_GET`— y permite validarlo o filtrarlo. `FILTER_VALIDATE_INT` comprueba que `page` sea un entero: devuelve `false` si el valor no es válido y `null` si el parámetro no existe. Es útil para comprobar que los datos recibidos tienen el formato esperado antes de utilizarlos.

Para construir una URL con parámetros se puede utilizar `http_build_query()`, que codifica correctamente los valores:

```php
<?php
$query = http_build_query(['search' => 'PHP y formularios', 'page' => 1]);
$url = 'search.php?' . $query;
```

En este ejemplo, `$url` contendrá `search.php?search=PHP+y+formularios&page=1`: `search` y `page` son los nombres de los parámetros, y `&` los separa. `http_build_query()` codifica los espacios como `+`.

No se deben incluir en una URL contraseñas ni información privada: pueden quedar en el historial, los marcadores o los registros del servidor.

## 3. Formularios HTML

Los formularios permiten enviar datos al servidor. El atributo `action` indica el destino y `method` el método HTTP. Cada control que se quiera enviar debe tener `name`; ese nombre se utiliza como clave al leer los datos en PHP.

```html
<form action="greeting.php" method="get">
 <label for="name">Nombre:</label>
 <input type="text" id="name" name="name" required>
 <button type="submit">Enviar</button>
</form>
```

Al enviar el formulario, el navegador solicita una URL similar a `greeting.php?name=Alex`. El script puede leer el dato desde `$_GET`:

```php
<?php
$name = trim($_GET['name'] ?? '');

if ($name === '') {
  http_response_code(400);
  echo 'Debes indicar un nombre.';
  exit;
}

echo 'Hola, ' . htmlspecialchars($name, ENT_QUOTES, 'UTF-8');
```

`label` mejora la accesibilidad; su atributo `for` debe coincidir con el `id` del control. `name` es necesario para que su valor se envíe. Los controles deshabilitados o sin `name` no se incluyen en la petición.

### 3.1. Tipos de controles habituales

```html
<label for="email">Correo:</label>
<input type="email" id="email" name="email" required>

<label for="message">Mensaje:</label>
<textarea id="message" name="message" rows="4"></textarea>

<label for="course">Curso:</label>
<select id="course" name="course">
 <option value="php">PHP</option>
 <option value="html">HTML</option>
</select>

<label>
 <input type="checkbox" name="newsletter" value="yes">
 Quiero recibir novedades
</label>
```

Las casillas checkbox no marcadas no se envían. Para leer una casilla opcional, se puede comprobar su existencia.

Los botones de opción comparten el mismo `name` y envían el `value` de la opción seleccionada. Los campos ocultos también pueden modificarse desde el navegador y no deben considerarse confiables.

```php
<?php
$email = trim($_POST['email'] ?? '');
$message = trim($_POST['message'] ?? '');
$course = $_POST['course'] ?? '';
$wantsNewsletter = isset($_POST['newsletter']);
```

El servidor lee cada campo mediante su `name` como clave de `$_POST`. Si una casilla no está marcada, no se envía y `isset()` devuelve `false`. Conviene validar los valores recibidos antes de utilizarlos.

### 3.2. Envío con POST

Para enviar datos en el cuerpo de la petición se utiliza habitualmente `method="post"`:

```html
<form action="contact.php" method="post">
 <label for="email">Correo:</label>
 <input type="email" id="email" name="email" required>

 <label for="message">Mensaje:</label>
 <textarea id="message" name="message" required></textarea>

 <button type="submit">Enviar mensaje</button>
</form>
```

PHP accede a los valores mediante `$_POST`:

```php
<?php
$email = trim($_POST['email'] ?? '');
$message = trim($_POST['message'] ?? '');

if (!filter_var($email, FILTER_VALIDATE_EMAIL) || $message === '') {
  http_response_code(400);
  echo 'Revisa el correo y el mensaje enviados.';
  exit;
}

echo 'Hemos recibido el mensaje de ' . htmlspecialchars($email, ENT_QUOTES, 'UTF-8');
```

`filter_var()` aplica al valor indicado un filtro. En este caso, `FILTER_VALIDATE_EMAIL` comprueba si `$email` tiene un formato de correo válido: devuelve el valor si pasa la comprobación y `false` si no. No garantiza que la dirección exista ni sustituye al escape con `htmlspecialchars()` cuando se muestra en HTML.

`POST` no implica que los datos sean secretos ni que estén validados. Se debe utilizar HTTPS cuando corresponda y validar siempre en el servidor, aunque el formulario tenga atributos como `required`, `min`, `max` o `type="email"`. La validación del navegador mejora la experiencia, pero podría evitarse o manipularse.

!!! info "Información adicional"
    En formularios HTML, los tipos de contenido habituales son `application/x-www-form-urlencoded` y `multipart/form-data`. Este último se necesita para cargar archivos:

    ```html
    <form action="upload.php" method="post" enctype="multipart/form-data">
    <label for="document">Documento:</label>
    <input type="file" id="document" name="document" required>
    <button type="submit">Subir</button>
    </form>
    ```
    Los archivos se reciben en `$_FILES`, no en `$_POST`. La carga requiere comprobar errores, tamaño y tipo; no se debe confiar únicamente en el nombre o la extensión enviados por el cliente. Este contenido es complementario y no se evaluará en el examen.

## 4. Distinguir el método y procesar la petición

`$_SERVER['REQUEST_METHOD']` contiene el método de la petición. Un mismo script puede mostrar un formulario al recibir `GET` y procesarlo al recibir `POST`:

```php
<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
  $name = trim($_POST['name'] ?? '');

  if ($name === '') {
    http_response_code(400);
    echo 'El nombre es obligatorio.';
    exit;
  }

  echo 'Formulario recibido para ' . htmlspecialchars($name, ENT_QUOTES, 'UTF-8');
  exit;
}
?>

<form action="form.php" method="post">
 <label for="name">Nombre:</label>
 <input type="text" id="name" name="name" required>
 <button type="submit">Enviar</button>
</form>
```

Conviene comprobar que se recibe el método esperado. Es preferible utilizar explícitamente `$_GET` o `$_POST` en vez de mezclar fuentes mediante `$_REQUEST`.

## 5. Validación, escape y seguridad

Validar es comprobar que los datos tienen el formato y los valores esperados. Escapar es prepararlos para un contexto concreto, como HTML. Son tareas distintas:

- Validar en el servidor tipo, formato, longitud y límites permitidos.
- Escapar los valores al insertarlos en HTML para que no se interpreten como marcado o JavaScript.
- No considerar confiables los datos del usuario, aunque procedan de un formulario propio.

Para mostrar texto como contenido HTML se recomienda `htmlspecialchars()`:

```php
<?php
echo htmlspecialchars($userInput, ENT_QUOTES, 'UTF-8');
```

El escape no sustituye a la validación ni a otras medidas de seguridad.

## 6. Respuestas del servidor

PHP genera el cuerpo de la respuesta escribiendo contenido, por ejemplo con `echo`. También puede establecer el código de estado con `http_response_code()`:

```php
<?php
http_response_code(404);
echo '<h1>No se ha encontrado la página</h1>';
```

Algunos códigos frecuentes son:

| Código | Significado |
| --- | --- |
| `200` | Petición procesada correctamente |
| `201` | Recurso creado correctamente |
| `400` | Petición incorrecta o datos no válidos |
| `403` | Acceso prohibido |
| `404` | Recurso no encontrado |
| `405` | Método HTTP no permitido |
| `500` | Error interno del servidor |

Las cabeceras se envían con `header()` y deben establecerse antes de producir cualquier salida, incluidos espacios o líneas en blanco:

```php
<?php
header('Content-Type: text/html; charset=UTF-8');
http_response_code(200);
echo '<p>Respuesta del servidor</p>';
```

Para redirigir el navegador se puede utilizar la cabecera `Location`. Después de redirigir, se termina el script con `exit`:

```php
<?php
header('Location: thanks.php', true, 303);
exit;
```

El código `303 See Other` indica al navegador que solicite el destino con `GET`. La técnica *Post/Redirect/Get* consiste en redirigir después de procesar correctamente un `POST`, evitando que al actualizar la página se reenvíe el formulario.

## 7. Resumen del recorrido de los datos

1. El navegador envía una petición HTTP con un método y datos opcionales.
2. PHP obtiene los datos, por ejemplo, desde `$_GET` o `$_POST`.
3. El script comprueba el método y valida los datos recibidos.
4. El servidor establece el código de estado y las cabeceras.
5. PHP genera el cuerpo de la respuesta.
6. Antes de incluir datos del usuario en HTML, se escapan para ese contexto.

## 8. Resumen de funciones PHP

Estas funciones ayudan a normalizar y validar datos, evitar que entradas se interpreten como HTML y construir respuestas HTTP adecuadas. Deben utilizarse cuando la operación lo requiera; no sustituyen la validación ni las medidas de seguridad específicas de cada aplicación.

### `trim()`

Elimina espacios en blanco al principio y al final. Es útil para tratar una entrada formada solo por espacios como vacía y normalizar texto antes de validarlo.

```php
$name = trim($_POST['name'] ?? '');
```

### `isset()`

Comprueba si una variable o clave existe y no es `null`. Es útil para saber si se envió una casilla opcional, ya que las casillas sin marcar no se incluyen en la petición.

```php
$wantsNewsletter = isset($_POST['newsletter']);
```

### `filter_input()`

Obtiene una entrada externa y permite aplicarle un filtro. Con `FILTER_VALIDATE_INT` se comprueba que un parámetro sea un entero; también hay que comprobar que esté dentro de los límites aceptados por la aplicación.

```php
$page = filter_input(INPUT_GET, 'page', FILTER_VALIDATE_INT);
if ($page === false || $page === null || $page < 1) {
  $page = 1;
}
```

### `filter_var()`

Aplica un filtro a un valor. `FILTER_VALIDATE_EMAIL` comprueba el formato de un correo, pero no garantiza que la dirección exista. La validación en el servidor es necesaria aunque el formulario también valide en el navegador.

```php
$email = $_POST['email'] ?? '';
$isValidEmail = filter_var($email, FILTER_VALIDATE_EMAIL) !== false;
```

### `htmlspecialchars()`

Escapa caracteres especiales para mostrar texto de forma segura dentro de HTML. Es necesario al insertar datos no confiables en ese contexto, para que se muestren como texto y no como marcado o código.

```php
echo htmlspecialchars($userInput, ENT_QUOTES, 'UTF-8');
```

### `http_build_query()`

Codifica un array como una cadena de parámetros para una URL. Evita concatenar manualmente valores que pueden incluir espacios u otros caracteres especiales.

```php
$query = http_build_query(['search' => 'PHP y formularios', 'page' => 1]);
$url = 'search.php?' . $query;
```

### `http_response_code()`

Consulta o establece el código de estado HTTP. Permite comunicar al cliente si la petición se procesó correctamente o si se produjo un error.

```php
http_response_code(404);
```

### `header()`

Envía una cabecera HTTP. Debe llamarse antes de cualquier salida; se necesita, por ejemplo, para especificar el tipo de contenido o redirigir después de procesar un formulario.

```php
header('Location: thanks.php', true, 303);
exit;
```
